# Out of scope

Things deliberately not being built. Recording them here keeps them from being
re-proposed and re-litigated. Drawn from the product roadmap and CRUD specs that were
migrated out of the retired `.agent-os` scaffold.

## Not building

- **Teams / businesses** - no organization or company-account model.
- **Public API** - no REST/GraphQL surface for external consumers.
- **Real-time bank / payment-provider integration** - payments are entered manually or
  generated by the scheduler, never pulled from a bank feed.
- **Sharing a dataset between people (households / collaboration)** - each user gets a
  private, isolated dataset; data is never shared across users. The `owner` foreign key is
  the seam a household or sharing model could grow from later (ADR-0015).
- **Nested or hierarchical categories** - categories are a flat list.
- **Bulk category operations** - no bulk edit/delete of categories.
- **Offline / service-worker support** - Obol is an installable PWA (see below) but does
  not work offline.
- **Outbound notifications beyond email** - `symfony/notifier` is not installed; there is
  no SMS / push / chat delivery. Add it with `composer require symfony/notifier` if a real
  need appears.

## Superseded - now built

Decisions once recorded here that have since been reversed. Kept for traceability so the
reversals are explicit rather than silently dropped.

- **Multi-user** - ~~single-tenant with no accounts (ADR-0004).~~ Reversed by ADR-0014
  (passwordless authentication) and ADR-0015 (per-row ownership): accounts and per-user
  isolated data now exist. (Sharing that data between users stays out - see above.)
- **Multi-currency** - ~~costs are tracked in a single currency.~~ Reversed: costs carry an
  explicit currency (the `Money` value object) and cross-currency conversion is supported.
- **PWA install** - ~~web UI is the only target.~~ Partially reversed by ADR-0024: Obol is
  an installable PWA (manifest + home-screen icons + standalone launch). Offline support is
  still out (see above).
- **Category color and icon** - ~~categories carry a name only.~~ Reversed: a category now
  carries a color and an icon alongside its name. (Distinct from the application's own
  icon/favicon, which is also in scope.)
- **Mail and messaging** - ~~the mailer and Messenger infrastructure was removed as
  unused.~~ Reinstated and in active use: `symfony/mailer` sends transactional email
  (magic-link sign-in, address verification); `symfony/messenger` + `symfony/doctrine-messenger`
  back the command and query buses (a general-purpose `async` transport is wired but idle);
  and the event bus was reinstated synchronously (ADR-0011).

## Rejected implementation approaches (revisit on real need)

- **Inky for email templating** - transactional emails use a hand-rolled single-column
  base template (`templates/email/base_email.html.twig`) with `twig/cssinliner-extra` for
  CSS inlining, not `twig/inky-extra` / Inky. The emails are single-column, so Inky's
  component/table-grid machinery earns little here, and the Twig-native `inline_css` filter
  keeps rendering on the app's no-build path. This is not a maintenance judgment - Inky is
  actively developed (v1 tracks Twig 3.x; Inky 2 is a Rust rewrite with official PHP
  bindings and built-in inlining) - it simply does not pay for itself until emails need
  multi-column layouts. Revisit then; the base template is the seam to swap in.

## If one of these comes back

Reopen the decision explicitly (an ADR superseding the relevant point), rather than
quietly adding the feature. Several of these are load-bearing simplifications - e.g.
sharing a dataset between users would reopen the whole per-user isolation model.
